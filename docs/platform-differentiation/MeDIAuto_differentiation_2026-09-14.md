## 1. 핵심 제안 — 병리 AI 결과를 검토하고 수정하는 작업 공간

**MeDIAuto Studio는 대용량 병리 슬라이드 탐색, 정량 AI 결과 확인, 가상염색 비교, 조직·세포 주석 및 검수 작업을 웹 기반 작업 환경에 연결하는 플랫폼이다.** 차별화의 중심은 개별 AI 기능의 유무보다, 동일한 슬라이드 좌표를 기준으로 결과를 확인하고 사람이 수정하는 흐름과 이를 지원하는 서버 처리 구조에 있다.

현재 소스에서 확인한 주요 분석 계열은 Quanti HE, Quanti PD-L1, Quanti IHC, VS IHC다. VS IHC의 모델 등록은 현재 ihc_membrane 한 종류다. 분석 계열을 지원한다는 사실과 각 모델의 임상 성능이 검증되었다는 주장은 구분한다.

| 강조할 차별화 축 | 확인된 구현과 사용자 가치 |
| --- | --- |
| 탐색 중 필요한 데이터 우선 처리 | 현재 화면의 미생성 타일 요청을 우선 처리하고 서버 대기열·실행 수에 따라 즉시 생성 여부를 결정한다. 분석과 탐색이 함께 일어나는 환경의 응답성을 고려한 구조다. |
| 정량 결과를 원본 위치에서 검토 | 공간 격자로 화면 내 세포를 조회하고 확대 수준·세포 수에 따라 표시 방식을 바꾼다. 클래스와 신뢰도 필터로 검토 대상을 좁힐 수 있다. |
| 가상염색 생성과 비교 화면 연결 | 패치 추론, 겹침 영역 혼합, 타일 피라미드 생성, 원본 정렬 표시 및 split view를 연결한다. 생성 결과를 원본 위치와 비교할 수 있다. |
| AI 보조 작업과 사람의 검수 연결 | 필요 영역과 패치 작업, 세포 주석, 검수 상태를 관리한다. 정량 AI 원본 결과와 사용자별 수정 결과는 분리 저장한다. |

**추천 소개 문구**

“MeDIAuto Studio는 병리 슬라이드의 정량 AI 분석과 가상염색 결과를 원본 영상 위에서 검토하고, 주석·패치 작업과 사람의 검수로 연결하는 웹 기반 병리 AI 작업 플랫폼입니다. 현재 화면에 필요한 영상 처리를 우선하는 구조를 통해 분석과 탐색이 함께 이루어지는 작업 환경을 지원합니다.”

위 문구는 구현을 설명하는 표현이다. ‘세계 최초’, ‘유일’, ‘가장 빠름’, ‘진단 정확도 우위’, ‘등록 특허로 보호됨’을 의미하지 않는다.

특허 자료는 저장소의 출원 후보 요약, 네 건의 상세 HTML·DOCX 및 PDF 초안을 사용했다. 확인한 자료에는 출원·등록번호의 증빙이 없으므로 본 문서는 네 가지를 **특허 기술 후보**로 지칭한다. 시장 비교는 공개 제품 기능 비교이며 특허 신규성·진보성 또는 타사 권리 범위에 대한 판단이 아니다.

## 3. 특허 기술 후보 ①·② — 탐색 및 정량 결과 표시

### ① WSI Viewer 및 Adaptive Tile Streaming

**해결하려는 문제:** 대용량 슬라이드 전체 타일 생성이나 AI 작업이 진행되는 동안 사용자가 보고 있는 영역의 표시가 늦어질 수 있다.

**초안의 제안:** 화면에 필요한 타일을 우선하고, 미생성 타일을 즉시 생성할지 대기열에 넣을지 부하에 따라 선택하며, 임시 영상을 표시하는 클라이언트 동작과 서버 생성을 연결한다.

**현재 확인한 구현:** 타일 뷰어의 상위·하위 타일 대체 표시, 화면 요청 처리, 서버 우선 생성 요청, 실행 수·대기열 기준 inline 생성 제한, 사용자 활동에 따른 백그라운드 처리 양보가 존재한다. 주요 근거는 C1~C3다.

**특허 초안과의 간격:** 초안에 제시된 가시 면적·거리·대기시간·공유 사용자 수의 가중 점수식이 그대로 구현되었다고 확인하지 못했다. 현재 뷰어 활동 신호는 프로세스 전역 시각이며 사용자별 공정성 보장 스케줄러와는 다르다. inline 생성 허용 판단도 현재 코드에서는 실행 수와 대기열 길이가 핵심이다.

**문서에 사용할 표현:** “화면 요청과 서버 생성 우선순위를 연결하여, 탐색 중 필요한 타일 처리를 우선하도록 설계했습니다.”

**다음에 입증할 효과:** 캐시가 없는 슬라이드에서 동시 사용자 수를 늘리며 첫 유효 화면 표시 시간과 화면 이동 후 목표 해상도 완성 시간을 측정한다. 타일링 단독·AI 병행 조건의 p50/p95와 백그라운드 작업 완료 지연을 함께 기록한다.

### ② 대규모 병리 AI 정량 결과의 시각화

**해결하려는 문제:** 세포 결과를 모두 정밀 도형으로 그리면 확대·이동·필터 변경 중 화면 갱신 비용이 커진다.

**초안의 제안:** 원본 슬라이드 좌표로 정규화한 결과에 공간 인덱스를 구성하고, 화면·확대 수준·클래스·신뢰도 조건에 따라 필요한 표현만 그린다.

**현재 확인한 구현:** SpatialGrid 조회, 화면 범위 선별, 클래스·신뢰도 필터, 세밀한 세포 표시와 화면 해상도 기반 점 표시의 전환이 있다. `_renderCells`는 유효 MPP와 가시 세포 수를 사용한다. 히트맵 관련 표현도 별도 경로로 제공한다. 주요 근거는 C4다.

**특허 초안과의 간격:** 수백만 결과의 무지연 처리는 측정 결과가 아닌 목표다. 수정된 버킷만 갱신하는 최적화는 확인 범위에서 입증되지 않았고 전체 인덱스 재구성 경로가 존재한다. 공간 인덱스나 히트맵 자체의 독점성을 주장하지 않는다.

**문서에 사용할 표현:** “확대 수준과 화면 내 결과 수에 맞춰 표현을 조절하고, 원본 영상 위에서 정량 결과를 필터링하며 검토할 수 있습니다.”

**다음에 입증할 효과:** 같은 결과 집합에서 표시 정책 전환 전후의 프레임 시간, 필터 반영 시간, 메모리 사용량을 측정하고 세포 수·클래스·좌표의 보존 여부를 확인한다.

## 4. 특허 기술 후보 ③·④ — 가상염색 및 사람의 검수

### ③ Virtual Stain 생성 및 WSI Overlay

**해결하려는 문제:** 패치 단위 생성 영상의 경계를 완화하고, 큰 생성 결과를 원본 위치와 비교 가능한 형태로 전달해야 한다.

**초안의 제안:** 패치 추론 → 겹침 가중 혼합 → 타일 피라미드 캐시 → 원본 좌표 정렬 → overlay/split view를 연결한다.

**현재 확인한 구현:** 타일 스트리머의 누적·정규화, 디스크 기반 피라미드 생성, MPP를 이용한 표시 연결, 투명도·분할 비교, 모델 파일 식별값을 사용한 캐시 검사가 있다. 주요 근거는 C5~C7이다.

**특허 초안과의 간격:** 현재 등록된 VS 종류는 membrane 한 개다. ROI는 표시용으로 유지하되 추론에는 `roi_polygons=None`을 전달하는 경로가 있으므로 ‘선택 영역만 추론하여 비용 절감’이라고 설명할 수 없다. 미처리 영역 표시와 임상적으로 검증된 불확실성 지도도 서로 다르다. 캐시는 전체 전처리·추론 환경까지 포괄하는 완전한 재현성 기록은 아니다.

**문서에 사용할 표현:** “가상염색 생성 결과를 타일 피라미드로 구성하고 원본 슬라이드와 정렬해 비교할 수 있습니다. 모델이 변경된 캐시는 재사용하지 않도록 검사합니다.”

**다음에 입증할 효과:** 경계 이음새, 원본 대비 좌표 오차, 피라미드 수준 전환 품질, 모델 변경 시 캐시 무효화, 같은 조건의 재사용 시간을 측정한다. 실제 IHC와의 일치도는 별도 데이터와 검증 설계가 필요하다.

### ④ AI-assisted WSI Annotation Workflow

**해결하려는 문제:** 필요 영역 지정, 패치 라벨링, AI 보조 수정, 검수 상태가 분리되면 작업 누락이나 결과 추적의 어려움이 생긴다.

**초안의 제안:** WSI·패치·세포 좌표와 작업 상태를 연결하고 AI 결과에 대한 사람의 수정·검수를 이후 작업에 반영한다.

**현재 확인한 구현:** 필요 영역과 패치 작업, 주석·검수·종결 상태 필드, 역할에 따른 편집 제한, 세포 주석 저장·내보내기 경로가 있다. 정량 결과는 AI 원본과 사용자별 수정 데이터를 분리한다. 조직 주석 저장에는 버전 비교를 통한 충돌 검사가 있다. 주요 근거는 C8~C10이다.

**특허 초안과의 간격:** 세포별 수정 전후 이벤트의 완전한 이력, 차이 점수에 따른 자동 재검수 큐, 학습용 원본·수정 쌍의 표준 데이터셋, 자동 재학습·배포까지 이어지는 루프는 구현 완료로 확인하지 않았다. 조직 주석의 저장 충돌 검사를 모든 Cell 작업에 일반화할 수 없다.

**문서에 사용할 표현:** “AI 보조 주석과 사람의 편집을 패치 단위 작업·검수 상태에 연결하고, 정량 AI 결과와 사용자 수정 결과를 구분해 보관합니다.”

**다음에 입증할 효과:** 패치 좌표 왕복 정확성, 검수 반려 후 재작업, 저장·재열람·내보내기 일치, 역할 제한과 동시 편집 충돌 처리, 수작업 대비 소요시간을 확인한다.

## 6. 차별성을 입증할 시연과 평가 계획

제안 단계에서는 기능 목록보다 한 슬라이드의 작업 흐름을 보여주는 것이 효과적이다. 아래 순서는 제안한 시연 계획이며 실제 수행 결과가 아니다.

| 단계 | 시연할 사용자 행동 | 확인할 차별화 근거 |
| --- | --- | --- |
| 1. 슬라이드 탐색 | 아직 타일이 충분하지 않은 슬라이드에서 확대·이동한다. | 임시 영상과 목표 해상도 전환, 화면 요청 우선 처리 |
| 2. 정량 AI 검토 | 같은 위치에서 세포 결과를 보고 클래스·신뢰도 조건을 변경한다. | 좌표 정렬, 대량 결과의 표시 정책 전환, 검토 대상 필터 |
| 3. 가상염색 비교 | VS 결과를 켜고 투명도 및 분할 위치를 바꾼다. | 원본 위치와의 일치, 경계 품질, 비교 조작의 연속성 |
| 4. 조직 주석 | 비 Cell 뷰어에서 2 mm² 도형을 만들고 1·4·8 mm² 선택을 보여준다. | 화면 및 목록의 물리 면적 표시, 재열람 시 유지 |
| 5. 패치 작업·검수 | Cell 작업에서 필요 영역·패치를 선택하고 주석 후 검수·반려·재작업한다. | 좌표와 상태의 연결, 허용된 역할·상태에서만 편집 |

시연 화면에 사용할 슬라이드·결과·사용자 정보는 공개 가능한 자료로 구성한다. 이 문서에는 환자 영상이나 비공개 모델 파일을 포함하지 않았다.

**성능 평가 조건:** 동일 서버·GPU·저장장치·네트워크·브라우저·WSI·모델을 사용한다. 캐시 없음/있음을 나누고 타일 생성과 AI 추론 병행 여부를 기록한다. 동시 사용자 수 1·4·8은 초기 시험 조건의 예시이지 지원 규모의 약속이 아니다. 각 조건을 반복하고 중앙값과 p95, 오류율을 보고한다.

**업무 효율 평가:** 같은 과제를 수행하는 수작업과 AI 보조 작업을 비교한다. 검수 완료 시간, 수정 셀 수, 재작업률, 검수자 간 일치도를 기록하며 슬라이드 난이도와 순서 효과를 통제한다. 임상 정확도 비교와 소프트웨어 작업시간 비교는 별도 평가로 관리한다.

**기존 프로젝트 측정의 사용 범위:** 저장소의 개선 보고서에는 합성 문서 1,500건 환경에서 조회 50건의 처리시간 241.77→2.32 ms, 프로젝트 집계 240.76→53.71 ms가 기재되어 있다. 이는 해당 내부 쿼리의 변경 전후 측정값이며 본 문서 작성 중 재측정하지 않았다. 뷰어 체감 속도·추론 속도·타사 대비 성능으로 인용하면 안 된다. 근거: `reports/improvements_2026-09-14.md`.
