WSI Viewer 및 Adaptive Tile Streaming 방법

1. 발명의 명칭

대용량 병리 슬라이드의 웹 기반 표시를 위한 WSI Viewer 및 Adaptive Tile Streaming 방법

2. 기술분야

본 발명은 디지털 병리 영상 처리, 웹 기반 whole slide image viewer, 대용량 이미지 tile streaming, 다중 사용자 환경에서의 서버 부하 제어 및 viewport 기반 rendering scheduling에 관한 것이다.

3. 배경기술 및 문제점

Whole Slide Image(WSI)는 수 기가픽셀 이상의 해상도를 가지므로 일반적인 이미지 로딩 방식으로는 웹 브라우저에서 원활히 표시하기 어렵다. 기존 WSI viewer는 이미 생성된 tile pyramid를 읽어 화면에 표시하는 방식이 많으며, tile이 존재하지 않거나 특수 포맷에서 즉시 추출해야 하는 경우에는 사용자의 pan/zoom interaction이 지연될 수 있다.

특히 복수 사용자가 동시에 서로 다른 슬라이드 또는 서로 다른 위치를 탐색하면, 서버는 tile reading, resize, color correction, JPEG encoding, disk write, network response를 동시에 처리해야 한다. 이때 cache miss tile을 HTTP 요청 내부에서 무제한 생성하면 요청 thread가 장시간 점유되고, 전체 viewer 응답성이 급격히 저하된다.

또한 사용자가 빠르게 slide를 이동하거나 viewport를 변경하면 이전 viewport에 대한 tile 요청이 계속 처리되어 현재 화면과 무관한 타일이 생성된다. 이는 서버 자원을 낭비하고 새 viewport의 tile 표시를 늦춘다.

4. 해결하고자 하는 과제

  • 대용량 WSI를 웹 브라우저에서 부드럽게 pan/zoom 표시하는 것
  • 캐시된 tile은 즉시 제공하면서, 누락된 tile은 서버 부하 상태에 따라 즉시 생성 또는 queue 처리하는 것
  • 복수 사용자가 동시에 접근해도 현재 viewport에 필요한 tile을 우선 생성하는 것
  • slide 변경, zoom, pan에 의해 stale tile 요청이 발생한 경우 이를 빠르게 abort하고 새 viewport 기준으로 queue를 재구성하는 것
  • background full tiling과 viewer on-demand tiling 사이에서 사용자 체감 우선순위를 보장하는 것

5. 발명의 구성

5.1 Viewport 기반 tile 산출부

viewer는 현재 slide id, zoom level, viewport center, viewport 크기, stage downsample 정보를 이용해 화면에 필요한 tile 좌표를 산출한다. 산출된 tile은 현재 화면에 직접 표시될 child tile과 fallback에 사용될 parent tile로 구분된다.

child tile이 존재하지 않는 경우에도 parent tile 또는 thumbnail 기반 fallback을 먼저 표시하여 화면의 공백을 줄이고, child tile이 로드되면 fade-in 방식으로 교체할 수 있다.

5.2 Tile queue 및 우선순위 결정부

viewer는 산출된 tile task를 queue에 넣고, 현재 viewport 중심과 가까운 tile, child tile, 사용자가 현재 보고 있는 위치의 tile을 우선 처리한다. 이미 cache에 존재하거나 loading 중인 tile은 중복 queueing하지 않는다.

tile task에는 generation id를 부여하여 slide 변경 또는 viewport 변경 이후 도착한 stale response가 현재 화면 cache에 혼입되지 않도록 한다.

5.3 Abort 및 stale request 제거부

사용자가 pan, zoom 또는 slide 변경을 수행하면 viewer는 이전 generation의 in-flight image request를 abort한다. 또한 load queue와 loading set을 초기화하고 새 viewport 기준으로 tile task를 다시 산출한다. 이를 통해 현재 화면과 무관한 tile 요청이 서버와 브라우저 자원을 계속 점유하지 않게 한다.

5.4 Hybrid tile serving부

서버는 tile 요청 수신 시 먼저 disk cache 및 complete marker를 확인한다. cache hit이면 tile bytes를 즉시 응답한다. cache miss이면 다음 조건에 따라 inline generation 또는 queued generation으로 분기한다.

조건처리
viewer executor queue가 낮고 inline generation 수가 제한 이하짧은 timeout 내에서 tile을 즉시 생성하고 응답
background tile generation이 active이고 level이 높거나 특수 포맷인 경우priority queue 등록 후 빠른 queued response 반환
inline timeout 초과진행 중 작업은 완료 시 cache에 남기고, HTTP 응답은 queued 상태로 빠르게 반환
tile이 tissue/data envelope 밖에 있는 경우blank tile 또는 cache 가능한 빈 응답 반환

5.5 Priority tile generation부

cache miss tile이 요청되면 서버는 해당 tile이 포함된 stage-1 또는 stage-2 block 좌표를 priority set에 등록한다. background tile generator는 일반 순차 생성보다 priority set의 좌표를 먼저 처리한다. 이로써 사용자가 실제 보고 있는 위치의 tile이 full tiling 순서보다 앞서 생성된다.

5.6 특수 포맷 bridge 처리부

Philips iSyntax/i2Syntax 등 특수 포맷은 별도 bridge process를 통해 region extraction을 수행한다. viewer thread별 slide handling을 유지하고, bridge 결과를 raw image buffer 또는 임시 파일 방식으로 전달하여 반복적인 process startup과 PNG encode/decode 비용을 줄인다.

6. 구체적 제어 조건 및 데이터 구조

6.1 Inline generation 허용 조건

서버는 cache miss tile에 대해 다음 조건을 모두 만족하는 경우에만 HTTP 요청 내부에서 제한 시간 내 inline generation을 수행한다.

  • 현재 inline generation 작업 수가 미리 정한 최대 동시 처리 수 이하일 것
  • viewer executor의 대기 queue 길이가 임계값 이하일 것
  • tile level이 높은 경우, background full tile generation이 과도하게 CPU를 점유하지 않을 것
  • Philips/iSyntax 등 특수 포맷 tile의 경우 별도 bridge queue 또는 extraction latency가 임계값 이하일 것
  • 요청된 tile이 tissue/data envelope와 교차할 것

예시 조건식은 다음과 같다.

allow_inline = inline_active < max_inline && viewer_queue < queue_limit && !(background_generation_active && (tile_level >= 2 || is_special_format))

6.2 Queue 부하 판단 기준

queue 부하는 viewer executor의 대기 작업 수, inline generation active count, 최근 tile response latency, background tile generation 상태, AI worker active 여부 중 적어도 하나 이상을 이용하여 판단한다. 구현 예에서는 viewer queue length와 inline active count를 1차 gate로 사용하고, high-level tile 또는 특수 포맷에서는 background generation active 여부를 추가 gate로 사용한다.

6.3 Priority score 계산 요소

priority queue가 단순 set이 아니라 score 기반 queue로 구현되는 경우, 다음 요소를 이용하여 priority score를 산출할 수 있다.

요소설명예시 가중치
Viewport distancetile 중심과 현재 viewport 중심 사이의 거리가까울수록 높음
Visible intersectiontile 영역이 현재 viewport와 겹치는 면적겹칠수록 높음
Tile level현재 zoom에서 직접 표시되는 child tile인지 fallback parent tile인지직접 표시 tile 우선
User recency최근 interaction이 발생한 사용자 또는 slide 여부최근 viewport 우선
Request agequeue에 들어온 뒤 대기한 시간starvation 방지
Slide activity같은 slide를 보고 있는 사용자 수공유 효과가 큰 tile 우선

예시 score는 다음과 같이 정의할 수 있다.

score = 0.40 * visible_ratio + 0.25 * proximity + 0.15 * direct_level + 0.10 * recency + 0.05 * wait_age + 0.05 * shared_slide_count

6.4 Tile level별 timeout

inline generation timeout은 tile level 및 slide format에 따라 다르게 설정한다. 낮은 level의 작은 read는 사용자가 즉시 볼 가능성이 높으므로 상대적으로 긴 시간을 허용하고, 높은 level 또는 특수 포맷은 빠르게 queued generation으로 넘긴다.

구분예시 timeout처리 의도
Level 0약 1.4초확대 화면에서 직접 필요한 tile이므로 즉시 생성 기회 제공
Level 1약 1.0초중간 배율 tile. 지연이 길면 fallback 유지
Level 2약 0.7초read 영역이 커서 서버 점유 방지
Philips 등 특수 포맷약 0.65초bridge extraction 지연이 전체 서버를 막지 않도록 제한

6.5 Parent fallback 선택 방식

target child tile이 존재하지 않으면 viewer는 상위 level에서 동일 scene 영역을 포함하는 parent tile을 찾는다. parent tile 좌표는 child tile 중심 좌표를 parent level의 scene tile size로 나누어 계산한다. parent tile이 존재하면 해당 parent tile의 일부를 crop 또는 scaling하여 child tile 영역의 fallback으로 표시한다. parent tile도 없으면 thumbnail 또는 blank background를 표시한다.

6.6 Generation ID 생성, 비교 및 폐기 방식

viewer는 slide load, slide 변경, color mode 변경, major viewport 변경 또는 tile request abort 시 generation id를 증가시킨다. 각 tile request에는 요청 당시 generation id가 저장된다. tile image의 onload event가 발생하면 현재 generation id와 request generation id를 비교하고, 서로 다르면 해당 response는 cache에 저장하지 않고 폐기한다.

이를 통해 이전 slide 또는 이전 viewport에서 도착한 늦은 tile response가 현재 화면에 잘못 표시되는 것을 방지한다.

6.7 Multi-user 우선순위 충돌 처리

복수 사용자가 서로 다른 위치를 탐색하는 경우, 서버는 사용자별 viewport request를 하나의 priority set 또는 priority queue에 병합한다. 동일 tile 또는 동일 stage block에 대한 중복 요청은 하나로 합친다. 서로 다른 사용자의 priority가 충돌하면 visible intersection, request recency, wait age, shared slide count를 기준으로 정렬하되, 특정 사용자의 요청이 장시간 대기하지 않도록 wait age를 score에 반영한다.

7. Pseudocode 예시

아래 pseudocode는 변리사 검토 및 청구항 구체화를 위한 설명용 예시이다.

onTileRequest(slide, level, x, y): if cache.valid(slide) and tile.exists(level,x,y): return tile.bytes; registerPriority(slide, level, x, y); if !intersectsTissue(level,x,y): return blankTile; if allowInline(level, slide.format, serverState): result = runWithTimeout(generateTile(level,x,y), timeoutFor(level, slide.format)); if result.ready: return result.bytes; return queuedResponse(retryAfter=1);

onViewportChanged(): generationId += 1; abortInflightImages(); clearLoadingQueue(); visibleTiles = computeVisibleTiles(viewport, zoom); enqueue(childTilesFirst(visibleTiles)); enqueue(parentFallbackTiles(visibleTiles));

8. 동작 절차

  1. 클라이언트 viewer가 현재 viewport와 zoom level을 기준으로 표시 대상 tile 목록을 산출한다.
  2. viewer는 child tile을 우선 queue하고, 필요한 경우 parent fallback tile을 추가 queue한다.
  3. 서버는 요청 tile의 cache validity를 complete marker와 source file signature로 빠르게 확인한다.
  4. cache hit이면 tile bytes를 즉시 응답한다.
  5. cache miss이면 서버 부하 상태, inline active count, viewer queue size, background generation 여부, tile level, slide format을 확인한다.
  6. 여유가 있으면 제한 시간 내 inline tile generation을 수행한다.
  7. 제한 시간이 초과되거나 busy 상태이면 priority tile로 등록하고 queued response를 반환한다.
  8. 클라이언트는 fallback을 유지한 상태로 일정 시간 후 재렌더링하여 생성된 tile을 다시 요청한다.
  9. 사용자 viewport가 변경되면 이전 generation tile request를 abort하고 새 tile 목록으로 재정렬한다.

9. 효과

  • 1~2명 사용 시에는 tile miss도 짧은 시간 내 즉시 생성되어 기존 사용감을 유지한다.
  • 다중 사용자 접속 시에는 서버가 무제한 inline generation으로 포화되는 것을 방지한다.
  • 현재 보고 있는 viewport의 tile이 full tiling보다 우선 생성되어 체감 속도가 향상된다.
  • slide 이동 및 pan/zoom 시 이전 요청을 제거하여 렉과 불필요한 서버 작업을 줄인다.
  • 캐시 hit 경로와 miss generation 경로를 분리하여 응답 안정성을 높인다.

10. 청구항 초안

독립항 예시

대용량 병리 슬라이드 영상을 웹 viewer에 표시하는 방법에 있어서, 현재 viewport 및 zoom level에 기초하여 복수의 tile 좌표를 산출하는 단계; 상기 tile 좌표 중 현재 viewport 내 child tile과 fallback parent tile에 우선순위를 부여하는 단계; 요청된 tile의 cache 존재 여부를 판단하는 단계; 상기 tile이 cache에 존재하지 않는 경우 서버의 viewer queue 상태, inline generation 상태 및 background tile generation 상태에 기초하여 inline generation 또는 queued generation을 선택하는 단계; inline generation이 선택된 경우 제한 시간 내 tile을 생성하여 응답하고, queued generation이 선택된 경우 상기 tile을 priority queue에 등록하고 fallback 표시를 유지하도록 하는 응답을 반환하는 단계를 포함하는 방법.

종속항 후보

  • 상기 제한 시간이 tile level 또는 slide format에 따라 다르게 설정되는 방법
  • 사용자의 pan 또는 zoom event 발생 시 이전 generation의 in-flight tile request를 abort하는 방법
  • priority queue가 stage-1 block 좌표 또는 stage-2 block 좌표 단위로 관리되는 방법
  • background full tiling 중에도 viewer viewport에 대응하는 tile을 우선 생성하는 방법
  • 특수 slide format에 대해 별도 bridge process를 이용하여 tile region을 추출하는 방법

11. 선행기술 대비 차별 포인트

  • 단순 tile pyramid viewer가 아니라 cache miss 상황에서 inline generation과 queued generation을 adaptive하게 전환한다.
  • 다중 사용자 상황에서 서버 부하를 tile serving 정책에 직접 반영한다.
  • viewport 변경에 따른 abort와 generation id를 이용하여 stale tile 혼입을 방지한다.
  • background full tiling과 viewer priority tiling을 하나의 scheduling 체계로 결합한다.

12. 주요 선행 도구 대비 상세 차별성

아래 비교는 공개 문서상 확인되는 각 도구의 주된 기능 초점과 본 발명의 청구 대상이 되는 Adaptive Tile Streaming 방법의 차이를 정리한 것이다. 최종 출원 전에는 변리사를 통한 선행문헌 검색 및 청구항 보정이 필요하다.

12.1 OpenSeadragon 대비

OpenSeadragon은 고해상도 zoomable image를 웹에서 표시하기 위한 JavaScript viewer이며, DZI, IIIF, IIP, Zoomify, custom tile source 등 다양한 tile source와 viewport, overlay, multi-image 기능을 제공한다. 즉 OpenSeadragon의 공개 문서상 핵심은 client-side zoom/pan viewer 및 tile source abstraction이다.

본 발명은 단순히 tile source를 지정하여 이미 존재하는 pyramid tile을 표시하는 것을 넘어, tile이 존재하지 않는 cache miss 상황에서 서버가 해당 tile을 즉시 생성할지 queue에 넣을지를 동적으로 결정한다. 특히 viewer executor queue, inline generation active count, background generation state, tile level, slide format을 이용해 inline generation과 queued generation을 전환한다.

또한 본 발명은 viewport 변경 시 generation id를 증가시키고 이전 in-flight tile request를 abort하여 stale tile response를 cache에 넣지 않는다. 이는 client viewer의 pan/zoom 처리 자체가 아니라, server-side tile generation scheduling과 client-side stale response 폐기를 결합한 구성이다.

12.2 QuPath 대비

QuPath는 bioimage analysis를 위한 open-source desktop software로, 복잡한 이미지를 시각화하고 분석하며 annotation을 빠르게 수행하는 기능을 제공한다. 공개 사이트에서도 QuPath는 bioimage analysis, tutorial, annotation, open-source desktop application의 성격이 강조된다.

본 발명은 desktop application 내부의 image rendering 또는 analysis 기능과 달리, 웹 기반 다중 사용자 서버 환경에서 tile request를 처리한다. 특히 복수 사용자가 서로 다른 viewport를 보고 있을 때, 같은 slide 또는 같은 stage block에 대한 중복 요청을 병합하고, viewport distance, visible intersection, request age, user recency, shared slide count 등을 priority score로 반영한다.

따라서 차별점은 WSI를 볼 수 있다는 점이 아니라, 다중 접속 SaaS 환경에서 cache miss tile generation을 사용자 체감 우선순위와 서버 부하 조건에 따라 제어한다는 점이다.

12.3 ASAP 대비

ASAP는 digitized multi-resolution histopathology image를 위한 fast and fluid viewer이며, annotation 도구, segmentation mask 등 algorithm result overlay, OpenSlide 기반 multi-vendor format 지원, mini-map 및 field-of-view tracking을 제공하는 것으로 공개되어 있다.

본 발명은 fluid viewer 또는 annotation 도구 자체보다, tile generation이 아직 완료되지 않았거나 특수 포맷에서 tile을 즉시 추출해야 하는 상황을 대상으로 한다. cache hit tile은 즉시 응답하고, cache miss tile은 제한 시간 내 inline generation을 시도하되, 서버가 busy 상태이면 priority queue에 등록하고 parent fallback을 유지한다.

또한 본 발명은 background full tiling이 진행 중인 slide에서도 현재 viewport tile을 priority set에 등록하여 full tiling 순서보다 먼저 생성되게 한다. ASAP의 공개 기능 설명에서 확인되는 fast viewing 또는 annotation과 달리, 본 발명은 background tiling과 viewer on-demand tiling을 하나의 adaptive scheduling 정책으로 결합한다.

12.4 PathPresenter 등 상용 digital pathology viewer 대비

PathPresenter는 image management system, clinical viewer, consultation, education, biorepository, vendor-agnostic integration, AI readiness, simultaneous users 환경에서의 rendering speed 등을 강조하는 상용 digital pathology platform이다.

본 발명은 상용 viewer의 고속 rendering 또는 IMS 기능 일반을 청구하려는 것이 아니라, 고속 rendering을 달성하기 위한 구체적인 tile miss 처리 정책을 청구 대상으로 한다. 즉 서버가 현재 tile request를 처리할 때 inline active count, viewer queue length, tile level별 timeout, special format bridge latency, background generation status를 평가하여 inline generation, queued generation, parent fallback, retry response 중 하나를 선택하는 구체적 제어 절차가 핵심이다.

또한 multi-user 환경에서 사용자별 viewport request를 priority queue로 병합하고, 중복 stage block 요청을 제거하며, wait age를 score에 반영하여 특정 사용자의 요청이 장시간 밀리지 않도록 하는 starvation 방지 구성을 포함한다.

12.5 일반 digital pathology viewer 대비

일반적인 digital pathology viewer는 tile pyramid를 사전에 생성하거나 scanner/vendor format의 기존 pyramid level을 읽어 화면에 표시한다. 이러한 방식은 tile이 이미 존재하는 경우에는 빠르지만, cache miss, on-demand conversion, 특수 포맷 bridge extraction, background tiling과 viewer request가 동시에 발생하는 상황에서는 HTTP 요청이 장시간 blocking될 수 있다.

본 발명은 다음의 결합 구조를 통해 차별화된다.

  • cache marker 및 source signature를 이용한 빠른 cache validity 판단
  • cache miss tile에 대한 inline generation 허용 조건식
  • tile level 및 special format별 timeout
  • busy 상태에서 queued response와 parent fallback을 이용하는 non-blocking UX
  • 현재 viewport tile을 background full tiling보다 우선 처리하는 priority scheduling
  • generation id를 이용한 stale tile response 폐기
  • multi-user request 병합 및 starvation 방지 priority score

따라서 본 발명의 차별성은 "WSI를 타일로 보여준다"가 아니라, "타일이 없거나 생성 중인 상황에서 다중 사용자 웹 서버가 어떤 타일을 언제, 어떤 방식으로 생성하고, 사용자는 어떤 fallback을 보면서 끊김 없이 탐색하는가"에 있다.

12.6 변리사 검토용 차별성 한 줄 요약

본 발명은 기존 WSI viewer의 tile display 또는 annotation 기능이 아니라, cache miss 및 background generation이 발생하는 SaaS형 다중 사용자 WSI viewer에서 server load, tile level, slide format, viewport priority, generation id를 결합하여 inline tile generation과 queued tile generation을 adaptive하게 전환하는 구체적 streaming control 방법이다.
