**권한·저장 안정성·조회 성능 개선 결과 — 2026-09-14**

분석 보고서의 우선 문제를 기준으로 코드를 수정했다. 운영 DB/원본 슬라이드에 쓰기 작업을 하거나 실행 중인 서비스를 재시작하지 않았다. 서버 재시작 시 적용할 백엔드 코드와 이에 맞는 프론트엔드 변경이다.

**적용한 변경**

- 프로젝트·폴더·조직 주석 조회에 공통 인증을 추가했다.
- viewer는 파일 삭제/이동/상태 변경, 폴더 변경, 업로드, 임상정보 변경을 호출할 수 없도록 했다. 기존 `require_not_viewer` 정책에 맞춰 admin/doctor/labeler의 해당 변경 권한은 유지했다. 프로젝트 생성·변경과 삭제의 기존 admin/doctor 또는 admin 전용 제한도 유지했다.
- 인증 저장소 미연결 시 익명 admin 대신 503으로 거부한다. 미디어 티켓 인증도 계정 활성/잠금 상태를 일반 API와 동일하게 검사한다.
- 조직 주석 조회에 ETag를 추가하고 저장 시 If-Match를 요구한다. 다른 화면에서 이미 저장했다면 409를 반환하며, 프론트엔드는 편집 내용을 유지하고 내보내기 후 재조회·병합하도록 안내한다. 버전 없이 저장하는 이전 클라이언트는 428로 거부한다.
- 주석 파일은 임시 파일에 기록·flush/fsync한 뒤 원자적으로 교체한다. 쓰기/교체 실패 시 기존 파일을 유지한다. compare-and-replace lock은 현재 단일 애플리케이션 프로세스의 스레드 간 보호이며 여러 worker의 분산 잠금은 아니다.
- 새 감사 이벤트는 HMAC v2로 before/after, 사용자 에이전트, 추가 상세 필드까지 서명한다. 기존 이벤트는 기존 서명 방식으로 검증한다. 사후 위치 보강 필드는 서명 대상에서 제외한다. 원본 로그를 재서명하거나 DB 스키마를 변경하지 않았다.
- VS IHC 결과에 모델 파일 SHA-256을 기록한다. 수동 추론의 캐시 적중과 자동 AI의 캐시 존재 판단에서 이를 검사한다. 모델 변경 또는 기존 캐시에 식별 정보가 없으면 재분석 대상으로 처리한다.
- 모델 해시는 파일 경로·크기·수정/변경 시각·inode별로 캐시한다. 모델 교체는 실행 중 파일을 수정하기보다 새 파일을 배치한 뒤 원자적으로 교체하는 방식을 사용해야 한다. 메타데이터를 그대로 보존하는 인플레이스 수정은 지원하는 업데이트 방식이 아니다.
- 빈 필터와 ID 조회의 정렬 없는 페이지는 SQL LIMIT/OFFSET을 사용한다. 최상위 필드 포함 projection은 DB에서 필요한 JSON 키만 반환한다. 복잡한 필터는 기존 Python 판정 규칙을 유지하되 스트리밍해서 충분한 결과를 찾으면 읽기를 멈춘다.
- 프로젝트별 상태·AI 완료 집계를 PostgreSQL GROUP BY로 옮겼다. 작은 집계용 필드를 materialized CTE에서 한 번 추출해 큰 JSONB의 반복 압축 해제 비용도 줄였다.
- 폴더 트리와 프로젝트 파일 수 탐색을 I/O 스레드로 옮겨 API 이벤트 루프를 막지 않도록 했다. 오래된 목록이 보이는 문제를 피하기 위해 별도 TTL 캐시는 도입하지 않았다.
- 변경된 API 클라이언트를 불러오는 JS/HTML 의존성의 버전 URL을 갱신했다. CORS를 사용하는 경우에도 ETag를 읽을 수 있도록 헤더를 노출한다.

**성능 비교**

운영 DB 대신 테스트가 생성하고 종료하는 임시 PostgreSQL을 사용했다. 합성 슬라이드 1,500개에 사용하지 않는 큰 JSON 배열을 포함하고, 워밍업 후 각각 5회 실행한 중앙값이다. 조회 결과 및 집계 값이 기존 Python 동작과 같은지 함께 검증했다.

| 측정 범위 | 변경 전 | 변경 후 |
|---|---:|---:|
| 필요한 필드만 포함한 50개 페이지 조회 | 241.77 ms | 2.32 ms |
| 프로젝트 상태·AI 완료 집계 | 240.76 ms | 53.71 ms |

페이지 비교에서 전체 후보 문서의 JSON 직렬화 크기는 7,658,140바이트, 반환 페이지의 직렬화 크기는 3,925바이트였다. 이 수치는 PostgreSQL wire protocol의 실측 전송량이 아니다. 기존 경로는 후보 전체를 Python으로 가져온 뒤 잘랐고, 새 경로는 DB에서 50개와 필요한 키만 반환한다.

프로젝트 집계는 현재와 레거시 AI 모델 이름 전체를 사용해 비교했다. 표는 API/브라우저/파일 탐색까지 포함한 응답 시간이 아닌 저장소 처리 시간이다. 합성 데이터의 불필요한 JSON 크기가 크므로 실제 운영 데이터에서 같은 개선 배율을 보장하지 않는다. 실제 사용 중 화면의 p95와 GPU 추론 성능은 별도 측정 대상이다.

**검증 범위**

최종 실행 결과: 백엔드 94개 테스트 통과(임시 PostgreSQL 통합 테스트 포함), 프론트엔드 테스트 1개 통과. Python/JavaScript 구문 검사와 `git diff --check`도 통과했다. 기존 pydicom deprecated API 경고 1개가 남아 있다.

기존 테스트에 API 권한, 잠금 미디어 티켓, 동시 주석 저장, 파일 교체 실패, 감사 서명 변조/기존 서명 호환, 모델 교체 무효화 테스트를 추가했다. 임시 PostgreSQL에서 projection·null/누락 키·페이지 제한·복잡 조건·정렬 fallback·집계 호환을 검증한다. JavaScript 테스트는 If-Match 전송, 저장 성공 후 revision 갱신, 충돌 시 편집 유지, 조회 실패 후 저장 차단을 확인한다.

재현 명령:

```bash
cd backend
MEDIAUTO_TEST_POSTGRES_BIN=/home/user/anaconda3/envs/mediauto-postgres/bin \
  /home/user/anaconda3/envs/medicus-saas/bin/python -m pytest tests -q -s
```

```bash
node --test frontend/tests/api-annotations.test.mjs
```

다른 환경에서는 Python과 PostgreSQL 바이너리 경로를 맞춰야 한다. `MEDIAUTO_TEST_POSTGRES_BIN`을 지정하지 않으면 임시 PostgreSQL 통합 테스트만 skip한다. 운영 연결 문자열은 이 통합 테스트에서 사용하지 않는다.

**반영과 남은 범위**

백엔드를 재시작한 뒤 화면을 새로고침해야 프론트엔드와 If-Match 계약이 함께 적용된다. 이미 열린 화면에 저장하지 않은 편집이 있다면 먼저 내보내야 한다. 모델 식별 정보가 없는 기존 VS 결과는 다음 분석 요청이나 자동 작업에서 재계산되므로 최초 분석 시간이 늘어날 수 있다.

이번 변경으로 모든 분석 보고서 항목을 해결한 것은 아니다. 복잡한 조건의 SQL 변환과 정렬은 기존 동작을 유지하며, 세포 패치 저장의 revision, 사용자별 작업 소유권, 작업 결과 재다운로드, 다중 프로세스 실행, 프론트엔드 대형 모듈 분리, 실제 브라우저 부하·백업 복구 검증은 별도 작업으로 남아 있다. 서비스 재시작이나 GPU 추론·운영 데이터 부하 시험은 이번에 수행하지 않았다.
