GPU 설치 가이드

Windows / Linux 통합 설치기

Docker 앱 3.3.2-gpu 작성일 2026.09.16

설치 환경은 선택하고, 데이터는 PC에 보관합니다.

① 준비된 Docker GPU 환경 또는 ② GitHub 소스를 이용하는 네이티브 GPU 환경을 선택합니다. 두 방식 모두 PostgreSQL은 PC에 직접 설치하고, 사용 중 생성되는 데이터는 지정한 외부 폴더에 저장합니다.

선택앱 실행 환경이럴 때 선택
1. Docker GPU · 권장준비된 Linux 컨테이너
Windows에서는 WSL2 사용		동일한 실행 환경으로 설치·운영
2. 네이티브 GPUPC의 Python 가상환경
GitHub에서 소스 다운로드		소스 접근 및 직접 실행 환경 필요

시작 전에 준비할 것

  • 지원되는 Windows 10/11 x64 또는 Ubuntu 22.04 이상 / Debian 12 이상 x64 + systemd PC
  • NVIDIA GPU와 정상 동작하는 드라이버, 인터넷, 관리자 권한
  • 통합 설치 묶음 전체와 기존 모델 11개가 들어 있는 폴더
  • 슬라이드·패치·결과를 보관할 충분한 디스크 공간
작은 설치 묶음에는 모델이 포함되지 않습니다. install.sh 또는 install.bat만 복사하지 말고, 압축을 푼 전체 폴더를 유지하세요. 설치 후에도 실행에 필요한 파일이 있으므로 설치 폴더를 임의로 이동하거나 삭제하지 마세요.

이 가이드는 현재 통합 GPU 설치기를 기준으로 합니다. 이전 CPU 설치본의 자동 업그레이드 또는 기존 데이터 자동 이전 안내가 아닙니다. 네이티브 방식의 앱 버전은 선택한 GitHub 브랜치·태그·커밋에 따라 달라집니다.

01 · WINDOWS

Windows에서 설치하기

1. 드라이버 상태 확인

PowerShell 또는 명령 프롬프트에서 실행합니다.

nvidia-smi --query-gpu=name,driver_version --format=csv,noheader

GPU 이름과 드라이버 버전이 출력되어야 합니다. 오류가 나거나 드라이버가 오래됐다면 NVIDIA 공식 다운로드에서 GPU와 Windows에 맞는 드라이버를 설치하고 재부팅하세요.

앞서 확인한 471.41 / CUDA 11.4 환경은 이 설치기의 CUDA 12.8 환경에 맞게 드라이버를 업데이트해야 합니다. 정확한 GPU 모델의 지원 여부도 확인하세요. nvidia-smi의 CUDA Version은 드라이버가 지원하는 CUDA 수준이며, 별도로 설치한 Toolkit 버전이 아닙니다.

2. 설치 묶음 압축 해제

MeDIAuto-GPU-installer-windows-x64.zip

계속 보관할 위치에 전체 압축을 풉니다. 예: C:\MeDIAutoInstaller. 모델은 별도 폴더에 준비합니다. 예: D:\MeDIAutoModels.

3. install.bat 실행 → 설치 방식 선택

install.bat를 실행하고 관리자 권한 요청을 허용합니다.

1. Docker GPU environment + host PostgreSQL (recommended)
2. Native GPU environment from GitHub + host PostgreSQL
Choose installation method [1]:

Enter 또는 1은 Docker, 2는 네이티브 방식입니다. 입력 항목은 4쪽을 참고하세요.

4. Windows 안내에 따라 계속 진행

  • Docker 방식: WSL2 관련 기능, Docker Desktop, Python 및 PostgreSQL 준비를 진행합니다. 재부팅 안내가 나오면 재부팅 후 같은 install.bat를 다시 실행하세요. Docker Desktop의 첫 실행 안내도 완료해야 합니다.
  • 네이티브 방식: Python 가상환경, GPU 패키지, 영상 라이브러리와 PostgreSQL을 준비합니다. GitHub 인증 정보를 추가로 입력합니다.
  • winget이 없으면 안내에 따라 App Installer를 설치한 뒤 다시 실행합니다.

드라이버는 설치기가 자동 교체하지 않습니다. Windows Docker GPU 실행에는 Docker Desktop의 WSL2 백엔드와 해당 GPU 지원이 필요합니다.

02 · LINUX

Ubuntu / Debian에서 설치하기

1. GPU와 모델 폴더 준비

nvidia-smi
ls /mnt/models/mediauto

모델 경로는 예시입니다. 실제 모델 파일이 있는 경로를 사용하세요. 드라이버 오류가 있다면 먼저 해결하고 필요한 경우 재부팅합니다.

2. 설치 묶음 전체 압축 해제

설치 파일을 받은 디렉터리에서 실행합니다.

mkdir -p "$HOME/MeDIAutoInstaller"
tar -xzf MeDIAuto-GPU-installer-linux-x64.tar.gz \
  -C "$HOME/MeDIAutoInstaller"

압축 해제된 내용에서 install.sh가 있는 폴더로 이동한 다음 실행합니다. 묶음 내부에 상위 폴더가 있다면 그 안으로 이동하세요.

sudo -v
bash install.sh

sudo -v에는 현재 Linux 계정의 sudo 비밀번호를 입력합니다. 입력 중 글자가 표시되지 않는 것은 정상입니다. 비밀번호를 설치 파일에 저장할 필요는 없습니다.

3. 설치 방식 선택 및 설정 입력

기본값 1은 Docker GPU 방식입니다. 저장 경로 3개와 웹·DB 포트, 접속 범위를 입력합니다. 네이티브 방식은 GitHub 인증 정보도 입력합니다.

Docker 방식이 준비하는 항목네이티브 방식이 준비하는 항목
Docker Engine / Compose
NVIDIA Container Toolkit
GPU 앱 이미지
호스트 PostgreSQL		Python 가상환경 / GPU 패키지
OpenSlide / libvips 등 의존성
GitHub 소스 / systemd 앱 서비스
호스트 PostgreSQL

Docker의 GPU 연결 도구만 별도 설정할 때

통합 묶음의 최상위 폴더에서 다음을 실행할 수 있습니다.

sudo bash setup-nvidia-runtime.sh
이 명령은 NVIDIA Container Toolkit을 설정하고 Docker를 재시작합니다. 다른 컨테이너를 운영 중이라면 작업 시간을 고려하세요. NVIDIA 드라이버 자체를 설치하는 명령은 아닙니다.

GitHub 계정 비밀번호 대신 해당 저장소의 Contents 읽기 권한이 있는 PAT를 사용합니다. 공개 저장소는 GitHub ID를 비울 수 있습니다. PAT는 숨김 입력하며 설정 파일이나 로그에 저장하지 않습니다. 앱 로그인 계정과 GitHub 계정은 별개입니다.

설치가 끝난 뒤 접속

접속하는 PC브라우저 주소 · 웹 포트 18093 예시
설치한 PChttp://localhost:18093
같은 공유기의 다른 PChttp://서버의LAN주소:18093

서버 IP는 Windows의 ipconfig, Linux의 hostname -I로 확인합니다. 예시 IP 대신 실제 주소를 사용하세요. 원격 PC에서 localhost를 입력하면 그 원격 PC 자신에게 접속합니다.

최초 로그인

두 설치 방식 모두: 초기 관리자 ID는 admin, 초기 비밀번호도 admin입니다. 최초 로그인 정보는 <외부 루트>/config/ADMIN_LOGIN.txt에 보관됩니다. 기존 계정의 비밀번호는 재설치로 초기화되지 않습니다.

Docker 앱 시작·중지 · Linux 예시

sudo docker compose \
  -f /mnt/data/mediauto/config/compose.json \
  up -d --wait --wait-timeout 900

sudo docker compose \
  -f /mnt/data/mediauto/config/compose.json stop

실제 외부 루트로 바꿔 사용하세요. Windows는 PowerShell에서 sudo 없이 같은 명령을 한 줄로 실행하고, 파일 경로를 "D:\MeDIAutoData\config\compose.json"으로 바꿉니다.

로그 확인

# Linux
sudo tail -n 100 /mnt/data/mediauto/logs/app.log

# Windows PowerShell
Get-Content "D:\MeDIAutoData\logs\app.log" -Tail 100

Docker 앱은 외부 로그 파일을 사용합니다. docker logs 대신 위 파일을 확인하세요. DB 서버 로그는 database/log에 있습니다.

터미널을 닫아도 Docker 백그라운드 앱과 Linux systemd 앱은 계속 실행됩니다. 다만 PC 절전·종료 중에는 접속할 수 없습니다. Windows 네이티브 앱은 설치 사용자의 로그인 시 작업 스케줄러로 시작하므로 로그아웃 상태의 상시 서버 운영과는 다릅니다.

설치·접속 문제 해결

“address already in use” · 포트가 이미 사용 중

다른 앱이 해당 포트를 사용하고 있습니다. 새 설치에서는 웹 포트에 18094 등 빈 포트를 지정하세요. Docker 컨테이너 내부 앱 포트는 8092이며, 브라우저는 설치 시 지정한 호스트 웹 포트로 접속합니다.

같은 공유기에 있는데 다른 PC에서 접속되지 않음

  1. 먼저 서버 PC에서 http://localhost:설정한포트가 열리는지 확인합니다.
  2. Web bind가 0.0.0.0인지, 접속 주소가 실제 서버 LAN IP인지 확인합니다.
  3. 서버 방화벽의 웹 포트 허용과 게스트 Wi-Fi / AP 격리 여부를 확인합니다. Windows 설치기는 LAN 공유 설정에서 로컬 서브넷 규칙을 추가합니다.

같은 LAN 내부 접속에는 일반적으로 공유기의 인터넷 포트 전달 설정이 필요하지 않습니다. DB 포트를 클라이언트 PC에 공개할 필요도 없습니다.

GPU 오류 · 드라이버/라이브러리 불일치

호스트에서 nvidia-smi부터 확인합니다. 드라이버 업데이트 뒤 재부팅하지 않았다면 재부팅 후 다시 확인하세요. Docker만 GPU를 못 찾으면 Linux의 NVIDIA Container Toolkit 또는 Windows Docker Desktop WSL2 설정을 확인합니다.

이 설치기는 앱 시작 전 CUDA 행렬 연산과 torchvision NMS를 검사합니다. 실패하면 CPU로 자동 전환하지 않고 중단합니다. 일반적으로 별도의 시스템 CUDA Toolkit 설치는 필요하지 않으며, 이미지/패키지에 포함된 실행 라이브러리를 사용합니다.

APT “Conflicting values … Signed-By”

NVIDIA 저장소가 서로 다른 키 경로로 중복 등록된 경우입니다. 최신 설치 묶음의 setup-nvidia-runtime.sh에는 설치기가 만든 알려진 중복 NVIDIA/Docker 저장소 항목을 백업·정리하는 처리가 포함되어 있습니다.

sudo bash setup-nvidia-runtime.sh

Docker가 재시작됩니다. 여전히 실패하면 오류에 표시된 실제 저장소 파일을 확인해야 합니다. 모든 APT 저장소 파일을 일괄 삭제하지 마세요.

모델 누락·체크섬 불일치 / 기존 데이터 감지

모델 11개가 직접 들어 있는 폴더를 지정하고 파일이 완전히 복사됐는지 확인하세요. 기존 DB·설정이 다른 설치의 것으로 확인되면 덮어쓰지 않고 중단합니다. 설치를 다시 시도할 때는 같은 설치 폴더와 같은 방식을 선택하세요.

데이터 보존과 설치 방식 변경

앱 중지 또는 컨테이너 재생성으로 외부 데이터 폴더가 삭제되지는 않습니다. 백업에는 DB와 secrets, 결과·주석 및 필요한 원본 슬라이드를 함께 포함하세요. 실행 중인 PostgreSQL 데이터 폴더를 단순 복사하면 일관된 백업이 보장되지 않으므로 DB 백업 도구를 사용하거나 관련 서비스를 정상 중지한 상태에서 백업합니다.

설치 방식 선택은 자동 데이터 이전 기능이 아닙니다. 두 방식을 별도로 설치하려면 서로 다른 외부 루트와 포트를 사용해야 합니다. config에는 접속 정보가 있으므로 공개 저장소나 공유 자료에 포함하지 마세요.

이 안내서의 검증 범위

현재 Docker 이미지 haribo1/mediautoai:3.3.2-gpu는 PyTorch 2.11.0, torchvision 0.26.0, CUDA 12.8 환경입니다. Linux 호스트의 RTX 6000 Ada 2개에서 Docker 내부 CUDA 행렬 연산과 NMS 검사를 통과했습니다.

이 검사는 실제 슬라이드 전체 추론 성능 검증과는 다릅니다. Windows 전체 설치 및 각 GPU 기종의 호환성은 대상 PC에서 확인해야 합니다. Philips iSyntax SDK/라이선스는 포함되지 않습니다.
