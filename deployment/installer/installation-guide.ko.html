새 설치 준비

새 ZIP을 고정 경로에 풀고 Windows는 install.bat, Linux는 bash install.sh를 실행합니다. Conda가 없으면 공식 Miniconda로 설치합니다. 두 방식 모두 PC에 Git, GPU 앱 Conda 환경, Conda·Philips SDK 환경, PostgreSQL을 준비합니다. 1번은 Docker 이미지도 함께 빌드합니다. NVIDIA 드라이버는 정상 동작해야 합니다.

입력Windows 예시
설치 폴더C:\mediautoAI-dev\MeDIAuto-GPU-installer
설치 방식1 — Docker GPU 또는 2 — Native GPU
외부 저장 루트C:\mediautoAI-dev\data
모델 폴더기존 모델 11개 폴더
슬라이드 폴더엔터: 외부 루트/slides
웹 / DB 포트18094 / 55433 (사용 가능한 포트)
GitHub저장소, 브랜치/태그, 사용자명과 PAT

계정, DB, 로그, 패치와 결과 등은 외부 저장 루트에 저장합니다. 모델은 복사하지 않고 지정한 폴더를 사용합니다. SDK는 배포본에 포함되며 라이선스 동의가 필요합니다.

Conda 환경 활성화

conda activate medicus-saas
conda activate philips-sdk-py37

각각의 환경으로 전환하는 명령입니다. Linux Philips는 philips-sdk-py38입니다. 설치 후 새 터미널을 여세요.

설치 완료

서버는 자동 실행하지 않습니다. 로그인 자동 실행 작업도 등록하지 않습니다. PostgreSQL만 서비스로 유지합니다. 새 DB의 계정은 admin / admin1234!이며 기존 DB 계정은 자동 변경하지 않습니다.

구형 ZIP 소스 설치는 새 Git 폴더로 자동 변환하지 않습니다. 새 설치 폴더/외부 루트를 사용하고 기존 데이터는 보존하세요.

DEVELOP & RUN

VS Code와 직접 실행

소스 열기

VS Code에서 설치 폴더의 docker/application(1번) 또는 native/application(2번)을 엽니다. .git이 있는 실제 clone이며 브랜치 변경·병합·커스텀 개발이 가능합니다.

시작 / 종료

설치 폴더의 터미널에서 실행합니다.

1번 Docker: docker\start.bat / bash docker/start.sh
1번 로컬:   docker\start-local.bat / bash docker/start-local.sh
2번 Windows: native\start.bat
2번 Linux:   bash native/start.sh
종료: Ctrl+C (Docker는 stop.bat / stop.sh도 제공)

설정한 포트로 브라우저에 접속합니다. 예: http://localhost:18094. 같은 공유기의 PC에서는 서버 LAN IP를 사용합니다. 터미널을 닫아도 유지되는 백그라운드 실행 방식은 아닙니다.

1번은 docker/MeDIAuto-local.code-workspace를 열면 로컬 Python과 디버그 실행 구성이 준비됩니다. Docker와 로컬은 같은 소스·DB·포트를 사용하므로 한 번에 한 방식만 실행하세요.

브랜치 업데이트

  1. 서버를 Ctrl+C로 종료합니다.
  2. 로컬 변경을 커밋하거나 필요하면 직접 stash합니다.
  3. VS Code/Git에서 fetch, switch, merge를 직접 수행합니다.
  4. DB 변경 전 백업합니다. 네이티브 의존성 변경은 install 재실행, Docker 변경은 start의 빌드로 반영합니다.
  5. start 명령으로 서버를 직접 실행합니다.

설치기를 재실행해도 기존 Git 작업 폴더를 pull/checkout/reset/clean하지 않습니다. 브랜치와 로컬 수정은 유지됩니다. 이후 Git 인증은 VS Code/Git에서 별도로 설정하세요.

기존 자동 실행 해제

같은 설치 ID의 앱 작업은 새 설치기가 중지·비활성화합니다. 다른 설치 폴더의 예전 작업은 별도로 중지해야 합니다. 예전 데이터와 모델은 삭제하지 않습니다.

적용 범위

두 방식 모두 설치 후 앱 자동 실행이 없습니다. Docker start는 현재 Git 소스를 다시 빌드하고 실행하며 restart 정책은 no입니다. Docker 엔진과 DB 서비스는 유지됩니다. 실제 Windows 전체 새 설치와 분석 검증은 대상 PC에서 확인해야 합니다.
